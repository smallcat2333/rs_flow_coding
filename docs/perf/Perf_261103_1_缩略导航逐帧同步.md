# Perf_261103_1 缩略导航逐帧同步

## 1. 目标

### 1.1 优化对象与动机

用户反馈右下角缩略导航拖动不流畅。保留原生 mxOutline 导航、点击定位、缩放和全屏只读交互，优化当前实例的刷新调度与布局读取。

### 1.2 验收阈值（量化）

- 确定性调度基准：连续 120 次、间隔 4ms 的视口更新，在虚拟 60Hz 渲染循环中首次同步不超过一帧，输入持续期间仍有更新；每个渲染帧最多更新一次。
- 同一帧 100 次布局通知：布局读取由逐次执行降到最多 1 次。
- 首次载图同步刷新：只重建 1 次缩略 SVG，不留下重复绘制任务；后台载图确认继续不依赖动画帧。
- 正确性：末次视口坐标一致；完整更新请求不丢失；暂停、恢复与销毁时正确处理待执行任务；普通和全屏模式可用。

## 2. 基线

- 口径：从官方 mxOutline.js 加载真实调度函数，从 flow_bridge.js 提取真实接入代码；仅替换时钟、布局与 SVG 渲染端口，计数调用和调度延迟。
- 环境：本机 Node.js，确定性虚拟 60Hz 时钟；连续输入、布局突发和首次载图各运行 3 次。
- 限制：这是调度与重复工作量基准，不代表真实屏幕 FPS；浏览器预览另核验交互和最终坐标。
- 数据：连续输入共 476ms，期间视口更新 0 次，首次反馈延迟 486ms；同帧 100 次布局通知读取布局 100 次；首次载图同步绘制后仍有排队刷新，共复制 SVG 2 次。三次结果一致。

## 3. 优化记录

### 2026-11-03 当前实例按帧合并刷新与布局

- 依据：官方 `mxOutline.update` 每次清除旧定时器；4ms 连续输入会不断推迟 10ms 回调。现有 `placeMinimap` 对每次 SIZE / resize 通知立即读取布局。首次绘制直接更新 SVG 后又留下旧调度任务。
- 改动：`ui/flow_bridge.js` 仅替换当前 outline 实例的更新调度；`requestAnimationFrame` 合并同帧请求，保留完整更新标记；布局事件仅标记待定位；首次载图同步执行并取消排队任务；销毁时取消帧和布局监听。
- 对比：同一虚拟 60Hz 时钟、同样 120 次 4ms 输入，三次结果一致。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 输入持续期间的视口更新 | 0 次 | 28 次 |
| 首次反馈的调度延迟 | 486ms | 16.667ms |
| 总视口更新数 | 1 次 | 29 次，逐帧且无同帧重复 |
| 100 次同帧定位通知的布局读取 | 100 次 | 1 次 |
| 首次载图 SVG 复制 | 2 次 | 1 次 |
| 首次载图后的排队刷新 | 有重复绘制 | 无 |

- 上述延迟来自确定性事件循环模拟，不是实际用户拖动延迟或屏幕帧率。
- 流程图：无；仅调整内部绘制调度，业务流程、交互和数据不变。
