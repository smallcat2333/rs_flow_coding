# Perf_261106_2 Agent缩放跟随

> 状态：已验证待确认
> 应用：Flow Coding
> 创建：2026-11-06　　关闭：-

## 1. 目标

### 1.1 优化对象与动机

用户反馈节点旁的 Agent 标记在画布缩放时跟随缓慢，拖动跟随正常。保留标记的固定字号、点击打开会话、状态与发光框行为，优化缩放期间的位置同步。

### 1.2 验收阈值（量化）

- 在同一缩放预览路径下，画布视觉变换后标记的位置更新等待不超过 1 个渲染帧；连续缩放期间不等待缩放结束后才跟随。
- 标记、发光框与对应节点边缘的误差不超过 1 CSS px（含缩放预览与最终提交）。
- 空闲时不增加持续轮询；位置同步不重建标记内容。

## 2. 基线

- 口径：本机浏览器预览，`chat.drawio` 样例（67 个单元），真实 `graph.lazyZoom` 路径；每次以 scale=0.36 开始，连续因子=1.1，等待时间与实际 `wheelZoomDelay` 一致（150ms），运行 3 次。
- 指标：`zoomPreview` 事件时对比标记锚点与 CSS 变换后的节点锚点；记录该事件到 `zoomPreviewComplete` 的时间。只测 DOM 事件与坐标，不作为真实屏幕帧率。
- 数据：三次缩放预览时锚点误差 30.83 / 35.02 / 39.86 px（中位 35.02px）；预览到提交等待 161.7 / 171.4 / 173.3ms（中位 171.4ms）。现有逻辑在这段预览期间不更新标记，连续输入会不断推迟提交。
- 热点证据：`EditorUi.js` 在 `lazyZoom` 内立即设置 CSS transform 并派发 `zoomPreview`，仅在延迟提交后发出正式 SCALE / TRANSLATE；`flow_agents.js` 只监听后者。

## 3. 优化记录

### 2026-11-06 同步 CSS 缩放预览的位置

- 依据：`zoomPreview` 是画布已经开始视觉缩放的时机；现有标记要等延迟提交后才定位。draw.io 在此事件之后还可能修正连续滚轮的缩放原点，直接同步会使用中间原点。
- 改动：仅修改 `ui/flow_agents.js`，监听 `zoomPreview` / `zoomPreviewComplete`，同一任务末尾用微任务读取最终 CSS 比例与原点，投影节点边界，定位现有标记、发光框与涟漪；提交时恢复正式坐标。不修改 vendor，不引入空闲轮询，不缩放文字或重建标记内容。
- 同口径复测：仍为同一 67 单元图、scale=0.36、因子1.1、实际提交等待150ms、重复3次。预览同步耗时0.6 / 0.3 / 0.1ms，中位0.3ms；预览锚点误差0.040 / 0.031 / 0.047px，中位0.040px；最终提交后误差三次均为0。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| DOM 定位等待（中位） | 至少等待正式提交171.4ms | 同一任务微任务更新0.3ms |
| 预览节点锚点误差（中位） | 35.02px | 0.040px |
| 标记字号 | 12px | 12px |

- 上述耗时为浏览器 DOM 回调时间，不等于屏幕帧率或原生应用的输入延迟。
- 流程图：无；只调整内部显示定位，业务与图纸数据不变。
