## 1. 目标
### 1.1 优化对象与动机
Feat 顶部机器人点击后约 7～10 秒才出现 Agent 窗口；用户最初观察到等待后出现多个窗口，随后明确主要问题是启动慢，希望加快响应。优化现有会话打开和启动调度，不减少 CLI 的功能、工具或 hooks。

### 1.2 验收阈值
- 区分原生窗口出现、终端创建与 CLI SessionStart 就绪，不混报耗时。
- CLI 创建不得阻塞窗口 IPC：实际启动 Future 首次调度小于 1 秒。
- APP 汇总尚未完成时，已有会话仍能显示并开始连接；慢启动预览首屏小于 1 秒。
- 保留来源命名、唯一主会话、续接及失败重试行为。

## 2. 基线
- 用户实测：点击至窗口出现约 7～10 秒；原生窗口端到端耗时本轮未复测，因为现有应用托管着用户 CLI 进程，未重启替换。
- 环境：Windows / Rust debug 测试，独立 Flow Coding 数据目录；真实本机 Claude CLI、同一工作目录 E:/Project/GitHub/smallcat/flow_coding；只打开终端，不发提示、不调用模型。

- 真实前端启动段的受控基准：APP 汇总固定延迟 350ms，三次打开已有会话分别为 365 / 355 / 353ms，中位数 355ms。
- 已定位到根本原因：agent_create / agent_start 为同步 IPC，ConPTY 和子进程创建占用窗口线程；agent.js 启动又用 Promise.all 等待全部 APP 汇总后才显示并打开目标会话。CLI 自身初始化还有独立等待，本次不能把它算作已消除。

## 3. 优化记录
### 2026-11-06 启动离开窗口线程，首屏不等待 APP 汇总
- src-tauri/src/agent.rs：agent_create / agent_start 改为 async 命令，阻塞工作放入 Tauri spawn_blocking；保留原返回值、错误、来源命名及初始流程指令。原真实联调用例同步调整为等待 Future。
- ui/agent.js：APP 汇总独立加载，已有会话列表就绪后先绘制、打开目标会话并开始连接；汇总完成再补全关联信息。来源新建仍等待完整汇总，保留 Feat 关联节点。
- 流程图：无；只调整内部调度，不改变业务流程。
- 相同 350ms 汇总延迟、真实启动段：三次打开已有会话为 1 / 1 / 0ms，中位数 1ms；这是隔离调度基准，不是原生窗口或 CLI 就绪时间。
- 首次修改后真实 CLI 三轮：终端创建 183 / 575 / 147ms，SessionStart 5890 / 6883 / 5555ms；CLI 自身没有明显改善。
- 最终源码上的真实调度验证（期间并行会话新增 StatusLine 指标，内容完整保留）：

- 首次调度三轮均立即返回 Pending，未在调度线程创建终端；进程创建超过一秒时仍不占用该线程。CLI 就绪有 10.7 秒慢样本，不能承诺启动总耗时小于一秒；同期源码及机器负载变化也不支持把中位数小差异归因于本优化。
