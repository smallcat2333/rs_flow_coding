# Fix_261104_1 打开图纸偏边

> 创建：2026-11-04　　关闭：2026-11-04

## 1. 现象

### 1.1 问题描述

打开长图或跨图纸流程时，节点贴在可视区左侧或右侧，部分内容超出窗口；预期按最终可视区适应全图并居中。来源：用户截图与桌面反馈。

### 1.2 复现步骤

1. 打开图与 Feat 的组合页签。
2. 切换到纯流程图页签，再返回含长图的组合页签。
3. 检查 `电脑监控推送.drawio`、`飞书消息接入与问答流程.drawio` 和 `08_远程版本更新.drawio` 的中心与边缘。

### 1.3 影响范围

流程图首次打开、纯图与图加 Feat 页签切换期间的缩放和居中；不修改用户图纸、节点坐标或业务流程。

## 2. 根因分析

- `ui` 及其各级上级目录直到 `E:\` 均无 CodeGraph 索引，以源码和真实 WebView2 消息时序复核。
- 图文件可解析。`fitDiagramToWindow` 已按图形内容包围盒计算；原先关于“把整页空白纳入计算”的推断被实际源码与坐标排除。
- 原生跟踪记录 `.cache/open-fit-261104/baseline-trace.json`：图在 1776px 宽画布完成适应后，Feat 栏打开将宽度变为 995px，draw.io 随后又调整平移与滚动，最终中心横向误差约 390.40px。反向切换同样约 390.70px。
- 现有绘制回执只等待视图稳定，没有在布局改变后重新适应；稳定的错误位置因此也会被揭开。
- 本仓库 `docs/flow` 没有相关业务图；只修正绘制实现，不补图、不修改调用方业务流程。

**根因**：初始自适应先于栏布局和 draw.io 自身滚动调整完成，最终尺寸下没有重新适应居中。
**确信度**：已定位到根本原因，原生时序与两种切换方向的中心误差一致。

## 3. 修复方案

- 仅修改 `ui/flow_bridge.js`。复用原生 `fitDiagramToWindow`，在新图的画布尺寸变化和绘制稳定检查期间重新适应当前可视区。
- 用户平移、缩放、键盘操作、显式节点定位、保留同图更新视图和进入全屏时停止初始适应；保留现有定位与全屏浏览中心的优先级。
- 直接复用现有冻结层与绘制回执，不增加定时等待，不修改图纸模型和内容坐标。
- 编辑前基线 blob：`408e10ee2f533c834808cb8ac7c4d971fb6caca8`。本次改动包括适应标志、公共适应入口、尺寸监听与绘制检查调用，以及用户接管时清除标志。
- 实现及验收阶段不写 README、不暂存、不提交；等待用户确认后收口。
