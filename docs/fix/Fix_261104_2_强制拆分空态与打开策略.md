# Fix_261104_2 强制拆分空态与打开策略

> 状态：已关闭
> 应用：flow_coding
> 创建：2026-11-04　　关闭：2026-11-04

## 1. 现象

### 1.1 问题描述

用户反馈开启强制拆分后，跨应用点击图或 Feat 不替换当前内容而新建页签；两侧空位显示不同，流程图一侧还有旧工具栏和提示，Feat 一侧为整块深黑空白。

### 1.2 复现步骤

1. 开启强制拆分，从侧栏依次点击不同 APP 的内容。
2. 检查页签是否新建。
3. 分别关闭图与 Feat，比较两类保留空位。

### 1.3 影响范围

主窗口普通点击的本机偏好，以及图和 Feat 的空位显示；保留 Ctrl+点击新建和已打开内容优先切回的规则。

## 2. 根因分析

- 实际桌面环境：`forceSplit=true`、`projectsNewTab=true`，`fc-projects-new-tab` 未设置，使用了默认开启值。新建来自已有“不同项目在独立页签打开”选项，与强制拆分相互独立。
- 页签路由已有替换能力；通过现有设置将跨项目新建关闭并持久化为 `0`，无需修改路由或增加新配置。
- 图的空态位于编辑器内部，仍展示栏头与底部状态；Feat 空位直接隐藏正文和栏头，没有对应的空态。两种实现因此在位置、背景和提示上不同。
- 本次复用已核实无 CodeGraph 索引的 ui 目录源码；不改变业务流程图，不增加流程图资产。

**根因**：跨项目新建开关仍开启，加上两侧空位没有共用显示结构。
**确信度**：已定位到根本原因，实际本机开关与源码路由条件一致。

## 3. 修复方案

- 保留全部打开规则，通过现有设置恢复本机普通点击替换。强制拆分只控制布局。
- 两侧使用同款灰蓝空态，统一图标、标题、说明和居中位置，覆盖旧工具及正文；浅色主题同步适配。
- 保留原 `empty` 元素身份和图加载/关闭调用，仅将可变化的提示文字放在独立节点，避免覆盖图标结构。
- 根据用户追加要求，移除侧栏 Chart / Feat 标题的整行边框和默认底色，保留折叠、新增、计数和未读提示。
- 实现与验证阶段不修改 README、不提交，待用户确认后收口。
