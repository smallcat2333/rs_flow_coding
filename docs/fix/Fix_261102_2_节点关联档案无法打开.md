# Fix_261102_2 节点关联档案无法打开

> 状态：已关闭（用户授权统一提交）
> 应用：rs_flow_coding
> 创建：2026-11-02　　关闭：2026-11-03

## 1. 现象
用户点击 rs_bot_sever/chat.drawio 节点的 Feat_260901_2 书签后没有打开档案；窄窗口的 draw.io 顶部路径覆盖菜单。

## 2. 根因分析
- 实地检查 rs_bot_sever/docs/feat：没有 Feat_260901_2；该编号存在于 app_aging_process_monitoring/docs/feat，属于其他 APP。
- onNodeSelect 仅按当前 APP 查找，空结果静默返回。
- 书签仅调用 setSelectionCell，已选中节点再次点击不会触发 CHANGE，不能重新打开选择入口。
- embed 顶栏使用完整路径作标题，状态文本未按菜单占用宽度限制。
**确信度**：已定位到根本原因。

## 3. 修复方案
- 本 APP 缺失标签档案时给出明确提示，列出其他 APP 同号档案供手动查看，不自动建立跨 APP 关联。
- 书签重复点击显式发送选中事件。
- draw.io 顶栏显示短文件名，剩余宽度不足时省略，完整路径留作悬停提示。

## 4. 验证记录
- 通过：本 APP 正常关联、悬挂标签提示、重复书签点击、选择框 Esc、窄窗口路径省略。
- 物理重命名的 Rust 测试已通过：保留 Feat 编号与换行，拒绝同名覆盖和 Agent 锁；同步引用、历史登记和启停元数据，且不误改 mychat.drawio 等相似文件名。
- 原生已验证：鼠标双击 Feat 条目可更名；两个弹窗均打开时，主窗口树上的流程图更名同步到弹窗，Feat 引用更新。
- 原生已验证：失效标签提示能提供其他 APP 的同号档案；已选节点重复点击书签仍打开选择入口；用户手动选择后能在 Feat 弹窗打开其他 APP 的档案。
- Windows 磁盘 CRLF 按 CodeMirror 的 LF 文档规则比较，避免误判未保存；失败提示在刷新后保持可见。
- 最终原生回归通过：Windows 路径仅显示文件名，窄窗口状态区起点不小于菜单右边界，完整路径悬停提示正确；全部窗口正常退出。
