# Fix_261105_1 尺寸通知误弹窗

> 状态：已关闭
> 应用：flow_coding
> 创建：2026-11-05　　关闭：2026-11-06

## 1. 现象

### 1.1 问题描述

用户反馈切换或打开流程图时偶尔弹出 `Error: ResizeObserver loop completed with undelivered notifications.`，点击确定后可继续操作。预期尺寸观察通知不打断编辑器。

### 1.2 复现步骤

1. 打开流程图或图与 Feat 的组合页签，切换页签或调整布局；通知为偶发。
2. 最小确定性复现：在实际 draw.io iframe 内分发可取消的同消息 `ErrorEvent`，观察原生全局错误处理是否调用 `alert`；验证时临时记录 alert 调用，随后恢复。
3. 修复前分发 `ResizeObserver loop completed with undelivered notifications.`，记录到同内容 `Error: ...` 弹窗调用，事件未被取消。

### 1.3 影响范围

主编辑器的尺寸通知报告；桥接层由主窗口、独立流程图窗口及历史预览复用。不修改图纸、节点或布局算法。

## 2. 根因分析

- 2026-11-05 源码核对：draw.io `App.main` 安装的 `window.onerror` 会把全局错误交给延迟 alert；后续初始化也可能替换该处理器。
- 历史预览在 `ui/timeline.js` 中已有两种 ResizeObserver 通知的精确过滤，主编辑器没有。
- 实际 draw.io iframe 的最小事件复现确认此消息会进入 alert 链路。尚未确定是哪一个 ResizeObserver 触发偶发通知，本次仅修复通知被当作致命错误弹出的行为。
- `docs/flow` 无相关图；属于错误报告实现细节，不补图。

**根因**：主编辑器把 ResizeObserver 的循环通知交给 draw.io 全局异常弹窗处理，造成操作中断。
**确信度**：已定位到根本原因（弹窗链路已复现；触发通知的具体观察器未定位）。

## 3. 修复方案

- 在 `ui/flow_bridge.js` 初始化时添加捕获阶段错误监听，仅精确处理 `ResizeObserver loop completed with undelivered notifications.` 与 `ResizeObserver loop limit exceeded`。
- 匹配时记录控制台警告，取消默认报告并阻止继续进入 draw.io 全局异常弹窗；其他错误原样传递。
- 捕获监听不依赖 `window.onerror` 的安装或替换时机。
- 实现、验证阶段不写 README、不暂存、不提交。

## 4. 验证记录

- 修复前：实际 iframe 分发第一种通知后，记录到一次原生 alert 调用，事件未被取消。

- 2026-11-05 浏览器实际 draw.io iframe 共 7 次确定性事件验证通过：两种精确通知均被取消并仅记录 warn；普通错误、消息加后缀的相似错误仍调用 draw.io 原 alert；将 `window.onerror` 替换为后续处理器后，两种通知仍被拦截，普通错误正常到达新处理器。
