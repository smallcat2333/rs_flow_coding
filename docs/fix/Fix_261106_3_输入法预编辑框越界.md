# Fix_261106_3 输入法预编辑框越界

> 状态：已验证待确认
> 应用：Flow Coding
> 创建：2026-11-06　　关闭：-

## 1. 现象

### 1.1 问题描述

用户反馈 Agent 内嵌 CLI 输入中文时，输入法预编辑文字经常超出终端右侧宽度。预期组合输入保持可见，并将候选窗锚点留在当前终端范围内。

### 1.2 复现步骤

1. 打开 Agent 会话，让终端光标位于行尾附近。
2. 使用中文输入法连续输入尚未提交的文字；在浏览器中以 composition 事件及 textarea 值模拟同一路径。
3. 比较 `.composition-view` 与 `.xterm-screen` 的右边界。

已复现环境：Windows 11、项目内置 xterm.js、浏览器预览。110 列终端中光标位于第 107 列（从 0 起），单元格约 7.618 × 17 px，剩余约 23 px；预编辑框宽 99.03 px、右边界 1352.8，终端右边界 1276.66，越界约 76.17 px。

### 1.3 影响范围

Agent 窗口的中文、日文等组合输入预编辑显示及候选窗锚点。中文提交后的字符单元格宽度已测得 2、0、2、0、1、1、1，符合宽字符规则。

## 2. 根因分析

- 2026-11-06：走查 `agent.js → Terminal.open → xterm CompositionHelper`。预编辑框使用 `white-space: nowrap`，以终端光标列作为 left，仅随文字增长宽度，没有终端右边界约束。
- 2026-11-06：预编辑期间隐藏 textarea 跟随预编辑框定位，原实现同样没有约束右边界。
- 截图中候选窗的具体原生定位表现无法由浏览器合成事件证明，保留为实际输入法环境的验证限制。

**根因**：xterm 预编辑浮层直接从光标向右扩展，缺少边界避让；行尾剩余空间不足时覆盖终端外侧。

**确信度**：已定位到根本原因（源码定位规则与实测越界尺寸吻合）。原生候选窗最终位置仍取决于操作系统及输入法。

本次只修正终端输入法显示细节，不改变业务流程图。

## 3. 修复方案

- 新增 `ui/agent_ime.js` 适配层，作为终端 addon 在 `term.open` 后挂载；不修改 vendor。
- 正常情况下保留光标锚点，右侧空间不足时向左避让；文字长于整行时约束最大宽度并横向滚动显示末尾。
- 预编辑期间同步约束隐藏 textarea，使候选窗锚点保持在可见终端内；结束后恢复 xterm 自身布局。
- 监听预编辑更新及终端尺寸变化，终端销毁时清理资源。
- `ui/agent.js` 仅增加 `term.loadAddon(new AgentImeAddon());`，`ui/agent.html` 仅增加脚本引用；`agent.css` 无改动。
- 版本与 README 由共享工作区的统一版本维护会话协调；当前修复尚未提交。
