# Fix_261105_2 控件导航被长文本撑宽

> 状态：已关闭
> 应用：flow_coding
> 创建：2026-11-05　　关闭：2026-11-06

## 1. 现象

### 1.1 问题描述

用户截图中，Feat 控件页导航被较长的应用说明撑宽，正文被挤成接近单字宽的竖排。预期左右布局时导航保持既定宽度，不随内容扩张。

### 1.2 复现步骤

1. 在浏览器开发预览中，用模拟层新增临时 Feat，应用说明含多应用名与较长中文说明，章节名含长英文标识。
2. 将控件页可用宽度调整到约 736px（整体预览视口 2400×1100，保留现有分栏）。
3. 打开临时 Feat：修复前导航实际宽约 681.81px，正文仅约 53.69px，重现挤压。

### 1.3 影响范围

Feat 控件页导航的 Flex 宽度约束和元信息溢出显示，不改变档案内容、正文或阶段导航逻辑。

## 2. 根因分析

**根因**：`.fb-rail` 的 `flex-basis:160px` 没有覆盖默认 `min-width:auto`，长应用说明的内容最小宽度优先于预期宽度；元信息仅在部分宽度下截断，也会在其他宽度溢出。
**确信度**：已定位到根本原因，真实控件页样例重现导航 681.81px、正文 53.69px。

## 3. 修复方案

- `ui/feat_board.css`：给 `.fb-rail` 添加 `min-width:0`，让 160px 的固定 Flex 宽度生效。
- 所有宽度下的 `.fb-meta-item` 均按单行省略显示，删除窄栏媒体规则中的重复定义。
- 目录项 `.fb-toc li` 允许收缩且最大宽度不超过所属目录，避免窄栏横排时长章节名撑出导航边界。
- 沿用 520px 以下的顶部导航布局，不改变其业务行为。
- CSS 编辑前基线 blob：`84d232f4de859d58c8f10848594ab7a1b5709fa6`。
- 没有相关业务流程变化，不修改流程图；验证期间不写 README、不提交。
