# Fix_261106_1 Agent启动等待

> 状态：已关闭
> 应用：flow_coding
> 创建：2026-11-06　　关闭：2026-11-06

## 1. 现象
### 1.1 问题描述
V.0.2.21 启动后，主窗口直接提示“读取 Agent 失败：Agent 服务未初始化”。用户明确要求保留主窗口立即显示，允许 Agent 处于正在启动状态，并设置等待超时；不采用等待 Agent 就绪才显示主窗口的方案。

### 1.2 复现步骤
1. 启动 Flow Coding。
2. 主窗口开始加载侧栏与机器人状态；Agent 服务尚未完成初始化。
3. 页面立即读取 agent_list，收到“Agent 服务未初始化”，且不自动补齐初次会话列表。

### 1.3 影响范围
主窗口 Agent 列表、Feat/图机器人及 Agent 窗口的首次数据加载。流程图与 Feat 文件读写不受影响。

## 2. 根因分析
- lib.rs setup 先显示主窗口，再创建悬浮窗，最后同步调用 agent::init。
- agent_list 立即读取 HUB；HUB 尚未设置就报错。侧栏与机器人初始化调用没有等待就绪的机制。
- 已运行进程的本机 Agent 监听随后建立，说明本次提示为初始化期间的时序竞争，不是持久服务故障。

**根因**：前端读取会话早于服务初始化完成，正常启动状态被当作失败。
**确信度**：已定位到根本原因。

## 3. 修复方案
- 保留主窗口先显示；服务初始化放到后台线程，并在创建悬浮窗之前派发。
- Agent 数据读取及新建/启动入口使用同一就绪信号；异步等待，最长 30 秒，不阻塞窗口线程。
- 初始化的文件/端口错误保留具体原因；不将损坏会话文件当空列表继续运行。
- 主窗口及 Agent 窗口显示正在启动，完成后自动填充；Feat/图机器人等待首次会话加载后再允许点击。
- 流程图：无；调整内部启动调度与状态反馈，不新增业务图。
